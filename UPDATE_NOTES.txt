GO REWRITE AND NORMALIZED STORAGE

Deploy the entire project, including Dockerfile, go.mod, all .go files, testdata/
and trailmix.html. Updating server.py alone does not install this version.
Keep the existing Turso credentials, PIN settings and database. Before first
migration, finish pending saves and download a complete JSON export. Migration
is automatic and transactional. Refresh all browsers after deployment.

The backend is now compiled Go, using only its standard library. Docker runs
Go tests, builds a static executable and uses a runtime image with no Python.
Current entities and run metadata are stored independently from audit history.
Routine saves read only a revision/request lookup and write only changed
entities plus new audit records. Browser acknowledgements/SSE send revisioned
patches instead of complete run snapshots. Full audit history remains in exports.
The last committed cache stays readable while a remote write is in flight.

Safety PIN and optional login cookie persist. Existing pending request IDs and
Python request digests are supported, including Unicode/float canonicalization.
Normal batches are atomic in three remote trips; fully duplicate retries use two
without rewriting current data. Lost commit confirmations invalidate the cache
and recover safely by retry. Bad actions/SQL failures roll back all batch rows.
All existing production, roster, assignment, configuration, delivery and station
keyboard behavior is retained. Cleared rework still goes directly to Sealing.

Old snapshot rows and audit rows are retained. Old snapshots become read-only
after migration to protect against stale Python writers. Do not roll back to
Python after the new backend has begun saving. Refer to README.md and
REMOTE_HOSTING.txt for deployment and compatibility details.
