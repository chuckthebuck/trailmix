TRAILMIX GO: EXISTING RENDER + TURSO SERVICE

DEPLOYMENT
1. Let browser outboxes finish, then download a full JSON export as a backup.
2. Replace the complete project contents at the existing GitHub repository root.
   Required build files: Dockerfile, go.mod, every .go file, testdata/ and
   trailmix.html. Include the supplied CI files and documentation as well.
3. Keep existing TURSO_DATABASE_URL and TURSO_AUTH_TOKEN values. The token is a
   database read/write token, never a public browser credential. Keep existing
   TRAILMIX_SAFETY_PIN and optional team sign-in settings unchanged.
4. Use the Docker runtime and supplied Dockerfile. It runs the Go behavior tests,
   compiles a static binary and copies it and CA certificates into an otherwise
   empty runtime image. No Python interpreter, writable disk or local replica is
   used in production. Health check: /healthz. Listen port: Render's PORT.
5. Keep one instance. Suggested runtime settings in render.yaml are
   GOMAXPROCS=1 and GOMEMLIMIT=384MiB for a 512 MB service. GOMEMLIMIT is a soft
   Go runtime memory target, not a guarantee of total process memory usage.
6. Wait for the log 'TrailMix Go is running', then refresh every browser. The
   response header X-TrailMix-Backend: go-normalized-v1 verifies the new runtime.

FIRST STARTUP / DATA SAFETY
Go reads the existing database, including both plain JSON and zlib-v1 snapshots.
Migration creates normalized tm_runs/tm_entities records and a separate audit
summary/request-result index. Existing append-only events and request digests
are preserved. Safety PIN, optional sign-in cookie, current run, roster,
configurations, in-transit packages, assignments, inventories and readings are
retained. Prior archived runs remain exportable. No manually entered migration
SQL, reset, or new database is needed.

The migration commits atomically before the service starts accepting requests.
An interrupted migration can be restarted. After migration, old runs snapshots
are read-only so an older Python process cannot overwrite current Go data. The
old process may reject writes briefly during a rolling deployment; keep pending
entries and retry after the new service is ready. Do not re-enter physical work.
Do not roll back to Python after Go begins saving. Original snapshots remain as
historical migration sources, not current writable state.

SAVE AND SYNC DESIGN
Normal saves read a small run revision plus matching request IDs. Only changed
current records and new audit events are written. Up to 50 queued actions commit
as one transaction with independent request IDs/audit events. New/mixed batches
use three remote round trips. Fully duplicate batches use two and write nothing.
SQL error or invalid action rolls back the complete batch. An unknown commit
outcome invalidates the cache; retry reads confirmed database state and retains
original IDs. No committed state is published speculatively.

Browsers initially receive current data and activity summaries. Later saves and
SSE updates carry revisioned patches. Missed revisions are recovered by fetching
confirmed state. Personal route assignment rules and package ownership still
apply. Before/after bag snapshots live in audit storage and full JSON/CSV exports.
SSE pings carry presence data, not the whole run. Health probes do not load history.
Old HTML clients are supported during rollout, but continue receiving larger
compatibility responses until refreshed.

LOGS
Batch saved includes save_seconds, database_trips and database_request_bytes.
HTTP acknowledgements also include lock/read/apply/encode/write/commit/publish
phase durations under timings. Go does not report Python's thread CPU counter.
Remote phases include transport/provider processing; they are not pure SQL
execution times. These measurements do not include all browser download time.

AUTHENTICATION
Team login remains optional. Set TRAILMIX_REQUIRE_ACCESS_CODE=1 together with
TRAILMIX_ACCESS_CODE to require it; otherwise no session login is needed.
TRAILMIX_HTTPS=1 secures optional sign-in cookies. Safety decisions still require
the persisted Safety PIN. An explicit TRAILMIX_SAFETY_PIN overrides/persists it.
The database URL/token and Safety PIN are never included in state or exports.
Coordinator permissions use roster roles, matching the existing team workflow.

LIMITS
One active backend owns live notifications. Exports and initial loads can still
be large; production saves do not transfer that history. The Go service requires
Turso and refuses an insecure/nonpersistent fallback. TRAILMIX_TEST_DB=1 permits
HTTP only to localhost for development tests and must not be set in production.
The image's compiled build and local gateway tests passed. The Docker daemon and
live Render/Turso service were not available for a live container/cloud test.
